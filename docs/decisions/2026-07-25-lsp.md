# Do not run a language server for F# navigation

> Decided 2026-07-25 · Superseded by nothing · Related: [AGENTS.md](../../AGENTS.md) "Finding F#
> symbols"

## Context

Text search cannot tell apart F# symbols that share a name. In this repo, `SessionId` is a type, its
companion module, a DU case constructor, and twelve record fields. `rg '\bSessionId\b'` returns 321
hits. 97 of them are the type. F# also infers most types, so the source often does not show the type
of a binding.

We integrated `fsautocomplete` (FSAC), the language server behind Ionide, and measured it. FSAC
0.83.0 (in nixpkgs) ran over MCP on a 4-core container against this repo (105 files, ~19k lines, 14
projects):

| | fsautocomplete | ripgrep |
|---|---|---|
| definition (warm) | 1–3ms, exact | ~9ms, 321 hits to read |
| references (warm) | ~80ms, 97 exact | — |
| hover / inferred type | ~2ms | not answerable |
| cold start | ~20s, ~1.3GB resident | none |
| first `references` call | ~12s (workspace-wide check) | none |

Warm queries beat ripgrep on speed *and* precision. Two findings cost the most to establish:

- **`.slnx` is not a problem.** FSAC parses `Yession.slnx` and loads all 14 projects with no
  configuration. We predicted this blocker. It does not exist.
- **The binary alone is not enough.** FSAC loads projects through MSBuild. Without `dotnet` on PATH,
  it starts cleanly, loads *zero* projects, and answers every query with
  `Couldn't find <file> in LoadedProjects`. A missing toolchain looks like a corrupt workspace. The
  whole fix is to put the `bin` of the devenv profile on the PATH of the server.

## Decision

Agents navigate F# with `rg` against declaration forms. We removed `fsautocomplete`.

## Consequences

The cost is per session, not per repo: ~20s and ~1.3GB every time, in a container that starts fresh.
Break-even is somewhere around a few dozen navigations per session. Below that, `rg` plus the
declaration-form discipline in AGENTS.md is cheaper overall.

At 19k lines the precision gap is real but survivable. A 321-hit result is skimmable. The
compile-order and top-down-scoping properties of F# make declaration-form search reliable.

The MCP bridge was also ~490 lines of transport code to maintain. Its failure modes are not obvious
(see the JSON-RPC trap below).

### What would change this decision

- `src/` growing several times over, where 321-hit results stop being skimmable.
- A language server with a warm cross-session cache, which removes the per-session 20s.
- Work that is type-driven rather than name-driven, where hover is the only answer.

### A trap if the bridge is ever revived

The request IDs of an LSP server occupy a separate namespace from the IDs of the client, and the two
collide freely. A JSON-RPC dispatcher must therefore key responses on the *absence* of `method`, not
on `id`. A dispatcher that keys on `id` silently resolves your pending request with a server request
that has the same ID. That reads as "the server returns nothing". It caused a full misdiagnosis
during this evaluation: `workspacePeek` appeared to find no projects.
