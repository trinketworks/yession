# UX review — basic task walkthrough (2026-08-21)

Method: I booted the real manager (`--auth localhost`, scratch data dir,
`YESSION_NESTED_SANDBOX=weak`). I drove headless Chromium over CDP through the basic flow of a new
user:

- Create a session on the manager page.
- Launch it.
- Open it.
- Send a chat message.
- Open a terminal.
- Run a command.

I took screenshots at 1440×900 and at a true-viewport 390×844 (ui-exploration skill). The findings
are prioritised.

## P0 — broken flow

1. **Created sessions vanish from the manager list.** `POST /sessions` answers with a fragment that
   shows the new row (`stopped` + Launch). Moments later, the `/sessions/rows` EventSource snapshot
   replaces `[data-sessions]` and omits never-launched sessions entirely. This happens under every
   filter (`?show=active` included), while SSR `GET /` still renders them. The row appears and then
   disappears in front of the user. The session can no longer be launched or archived from the UI at
   all, though it sits in `manager.json`. The rows stream renders from a different source than the
   page (live process set vs store). Repro: create a session, wait for the stream to connect, and
   watch the row go.

## P1 — high friction on the primary path

2. **Create doesn't launch.** The main flow is create → find the row → Launch → click the name link.
   The name becomes a link only once the session runs. That is three interactions before any work
   happens, and #1 currently breaks the middle one. Create should launch and navigate (or at least
   offer to).

3. **The display name never reaches the session.** A session created as "design review" opens with
   the header "session" and the raw 26-char ID. The title input is empty, and the name must be
   re-typed inside the session. `document.title` is "Yession" on every page, so tabs are
   indistinguishable.

4. **Session URLs are ephemeral ports.** Stop + relaunch moved the session from :39047 to :37263.
   The old URL refuses connections. Open tabs and bookmarks die with no redirect or message, and the
   manager row is the only way back. (Data and title do survive the relaunch. Only the address is
   lost.)

5. **Identity churns.** Each fresh browser profile or load minted a new animal name: five over one
   walkthrough. Three of them are visible in a single transcript as apparently different people, but
   all are the same reviewer. There is no visible way to see or change your own name. Any cookie
   loss or second device silently forks identity, and the roster keeps the stale names as separate
   participants.

## P2 — feedback and legibility

6. **First chat message clipped on desktop.** At load, the text of the first message is half-cut
   under the header/author row (fine at 390px).

7. **Chat empty state is a void.** A new session is a black expanse. It has no "nobody has said
   anything yet" and no pointer to the composer. The composer itself is an unmarked thin bar with a
   small "→" and no placeholder text. On mobile the affordance is near zero.

8. **"+ new" terminal gives no feedback.** The click silently starts the environment (`not started`
   → `running`). The terminal appeared only noticeably later, with no spinner or progress between
   the click and the terminal.

9. **Every page load logs two 401s** (`/queries`, `/me`) before the handshake completes. This is
   console noise that would mislead anyone who debugs, and a hazard if an error surface ever reports
   fetch failures.

## P3 — polish

10. **Filter chip semantics.** The "active" chip links to `?show=none`. Names and query values do
    not correspond (related to the split-brain of #1 between page and stream).

11. **MCP declare form floats detached** below the empty-state line, with its own duplicate
    NAME/ADDRESS/REACHES header row. It reads as a second table.

12. **Terminal chrome jargon.** "take", "↑ replay from the start", and the "✓ 0" exit badge are
    unexplained and have no tooltips.

13. **ProseMirror warns** that `white-space: pre-wrap` is not set on the editor. Multi-space and
    newline rendering in the composer is at risk.

## Addendum (2026-08-21, after triage)

- **#1 root-caused.** `ProcessManager.createSession` never calls `publishSessions ()`. The
  `/sessions/rows` retained snapshot therefore omits sessions created since the last launch, exit,
  or rename. Only pages that (re)connect the stream in that window see the vanish. The own page of
  the creator swaps from the POST answer and stays accurate, which is why the bug does not reproduce
  interactively. The manager & session UX work below fixed it.
- **#10 retracted.** Chip hrefs are toggle targets (`SessionQuery.toggling`). This is deliberate.
- **#4, #5, #8 skipped** by owner decision. #3 resolved by cutting naming from the manager side
  (naming lives in the session). The manager & session UX fixes cover #1, #2, #3, #6, #7, #9 (+#13).

## Addendum (after those fixes landed)

Three findings did not survive contact with the code, and two were bigger than reported:

- **#7 half-retracted.** The empty state of the chat is not a void. It stands an idle caret where
  the first message will land, and it is deliberately wordless (`View.chat` holds the reasoning).
  What was genuinely unmarked was the composer below it. The composer is a `contenteditable`, so the
  `placeholder:` utility on its field had never once applied. We added a placeholder and left the
  empty state alone.
- **#9 half-retracted.** The `401 /me` is the authorization protocol, not a fault. The 401 of the
  probe triggers the login bounce, and a 200-with-anonymous would be a worse contract. The
  `401 /queries` beside it was real: an EventSource opened before authorization was known,
  guaranteed to fail and to keep retrying. It now opens in the authorized branch of the probe.
- **#6 was worse than "clipped".** The `pt-6 -mt-6` of the sticky author line did neither thing its
  comment claimed. Measured, it put the name 48px below the column top instead of 24. It also laid
  the first message 16px up into an opaque band, while it extended its ground nowhere above the box.
  We fixed both halves. The leading gap of the timeline moved out of the padding of the scroller, so
  the pinned line can reach the top edge at all.
- **#2 shipped larger than proposed.** `POST /sessions` answers `303` to the stable open route of
  the session, so creating a session lands you in a running one. That is one act, not four.

## What held up

Contrast passed everywhere sampled (all ≥ 4.5:1). Focus rings are visible, and focus continuity
survives swaps. Icon-only controls carry aria-labels. There is no horizontal overflow at 390px.
Session history and title survive stop/relaunch.
